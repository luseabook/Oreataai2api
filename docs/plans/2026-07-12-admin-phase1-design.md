# 管理后台第一阶段改造设计

## 目标

在不改变 FastAPI 单体部署、不引入新的前端构建链的前提下，先关闭管理后台最容易导致配置损坏、运营误操作和数据盲区的边界问题：

1. 管理设置必须经过前后端双重校验，不能持久化会导致重启失败的值。
2. API Key 的空值、`0` 和正数必须保持各自语义。
3. 任务动作必须遵守任务状态机，终态任务不能被取消覆盖。
4. 任务、用量和上传列表必须使用后端分页与筛选能力，不能再静默截断前 50 条。

## 非目标

- 本阶段不引入 Vue、React、Vite 或独立前端服务。
- 本阶段不拆出 `ADMIN_HTML`，避免把高风险行为修复与结构迁移绑在一起。
- 本阶段不重做视觉系统、认证方式、WebSocket 或全部后台导航。
- 本阶段不删除或重命名现有管理 API。

## 后端契约

### 设置更新

`SettingsIn` 的已知 UI 字段改为嵌套 Pydantic 模型，同时允许未建模字段继续透传，保持已有运维脚本兼容。已知字段约束：

- `server.port`: `1..65535`
- `pool.min_accounts`: 非负整数
- `pool.maintain_target`: 非负整数
- 合并当前配置后必须满足 `maintain_target >= min_accounts`

设置保存响应增加 `restart_required`。只有端口等启动期字段发生变化时返回 `true`；前端必须明确提示需要重启。

### 任务动作

新增统一的任务状态判定：

- retry: `failed`, `expired`
- hydrate: `submitted`, `hydrating`
- cancel: `queued`, `running`, `submitted`, `hydrating`
- cancelled: 保持幂等
- 其他终态 cancel: 返回 `409 TASK_NOT_CANCELLABLE`

状态约束必须在服务端执行，前端只负责减少误操作，不能成为唯一防线。

### 分页列表

任务、用量、上传接口继续保留 `limit`、`offset`、`has_more`，并增加同筛选条件下的 `total`。这允许前端展示真实总数和页码，同时保持旧调用方兼容。

## 前端交互

### 设置

- 数字字段使用 `type="number"` 和浏览器边界属性。
- 保存前使用共享整数解析器，拒绝空值、非整数和越界值。
- API 校验错误转换成可读文本，不显示 `[object Object]`。

### API Key

- 空输入表示继承全局值。
- `0` 表示不限额，不能被 `||` 转换为空或 `null`。
- 正整数表示自定义额度。
- 列表状态使用后端规范化 `status`，区分 enabled、disabled、expired、deleted。

### 任务

- 只展示当前状态允许的操作按钮。
- 取消操作必须确认，并在请求期间避免重复点击。
- 服务端返回 `409` 时保留当前列表并展示具体错误。

### 列表筛选与分页

任务、用量、上传各自维护 `limit`、`offset`、`total`、`hasMore` 和加载状态。筛选提交时回到第一页，上一页/下一页使用服务端请求；空态、失败态和加载态必须可区分。

## 测试策略

1. HTTP 回归测试覆盖设置边界、重启提示、任务取消状态和分页 `total`。
2. 管理页结构测试固定筛选器、分页器、状态门控和 `0/null` 解析逻辑。
3. Node 语法检查确保嵌入 JavaScript 可解析。
4. 最后执行完整 `*_tests.py` 测试集。
