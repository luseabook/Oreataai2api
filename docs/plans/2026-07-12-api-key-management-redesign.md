# API Key 管理页改造方案

## 目标

将“客户”和“API Key”合并为一个管理对象。后台不再要求管理员先创建客户、再绑定 Key；每个 Key 自带客户名称、额度、权限和状态。

## 交互方案

- 主列表只展示客户 Key，列出客户名称、Key 前缀、状态、今日额度、访问范围和最后使用时间。
- 创建与编辑统一使用右侧抽屉，避免宽表格内大量输入框和横向滚动。
- 完整 Key 不随列表接口返回；点击“复制”时由已登录管理员单独请求密钥接口并写入剪贴板。
- 调用日志、素材记录、成本报表和审计日志放入“调用与报表”页签。
- 额度语义保持一致：留空表示继承系统设置，`0` 表示不限额，正整数表示明确上限。

## 数据与兼容性

- `api_keys.name` 作为客户名称，现有 `clients` 表和接口保留，兼容历史绑定数据及旧客户端。
- 历史 Key 若没有名称，页面回退显示原客户名称；保存后会写入 `api_keys.name`。
- 列表接口只返回脱敏前缀和当日请求/点数统计。
- 管理员密钥读取接口要求管理登录，不在普通列表、日志或 HTML 中暴露完整 Key。

## 边界条件

- 客户名称必填；图片、视频权限至少选择一种。
- 额度只接受安全范围内的非负整数。
- PATCH 未携带的额度字段保持原值，避免局部启停操作误清空额度。
- 新建 Key 可直接指定启用或停用；有停用原因时强制停用。
- 已删除 Key 不允许继续编辑、启停或删除。

## 验证范围

- API：创建、编辑、额度保持、密钥读取鉴权和列表脱敏。
- 页面：抽屉字段映射、额度 `null/0/正数` 语义、完整 Key 复制、XSS 转义。
- 回归：旧客户绑定数据、调用日志分页、成本报表、现有生成 API。
